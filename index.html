Audio ML · Producer Matching Platform

In Development Studios

indevelopmentstudios.com ↗

Upload a track. Get a sonic fingerprint. Match with producers who share your sonic DNA — no follower counts, no metadata, no algorithm gaming. Pure audio-based matching at every layer of the stack. Free tier and paid subscriptions, live in production.

The Matching Engine

Three independent signals feed each upload. fpcalc (Chromaprint) generates an acoustic fingerprint, MD5-hashed for exact-duplicate dedup. A 512-dimensional CLAP embedding — L2-normalized for cosine comparability — captures semantic similarity across the corpus. A RandomForest classifier predicts genre and subgenre; if style_confidence < 0.40 or the track is a statistical outlier, it labels "Experimental" rather than mislabeling. Match responses use a deliberate 3+2 split: three in-subgenre picks for precision, two cross-subgenre discovery picks to break filter bubbles.

Cross-Page File Carry via IndexedDB

The signup flow needed a binary audio file to survive a full page navigation from the anonymous upload page into authenticated onboarding. localStorage handles metadata, not binary files. Solution: IndexedDB with a 30-minute TTL. idbPutTrack(file) writes on upload; a module-scoped promise resolves idbGetTrack() at signup load. The carried file reuses preflight analysis; a re-selected file on step 5 overrides and triggers fresh analysis. No redundant GPU round-trips, no re-upload friction.

The RLS Policy Trap

Row Level Security enforces the daily match-reveal quota server-side. A non-obvious Supabase constraint surfaced during testing: an RLS policy cannot SELECT FROM auth.users — the authenticated role lacks permission, silently blocking all inserts. The fix: read tier from auth.jwt()->'app_metadata'->>'tier' inline in the policy — evaluates from the signed JWT without a table join. The track-limit trigger works because it runs as SECURITY DEFINER.

Entitlement Security Model

Any signed-in user could self-grant Pro by calling auth.updateUser({data:{tier:'pro'}}) — Supabase allows users to write their own user_metadata. Migrated all entitlements to app_metadata, service-role-writable only. Verified live: wrote user_metadata.tier='studio' from the console; the gateway still granted free and blocked paid stems.

Audio AI · Stem Separation Engine

ID.ai

idai.indevelopmentstudios.com ↗

Upload audio. Receive up to 10 isolated stems — vocals, drums, bass, guitar, piano, synth, and tool stems for karaoke splitting, denoising, and dereverberation. GPU-backed via Modal.com, live Stripe billing, WCAG 2.1 AA verified, CI green.

Model Selection & Evaluation

Benchmarked Kim FT Mel-Band Roformer, Demucs htdemucs_ft, four ensemble methods, cascade pipelines, and other-by-subtraction on an EDM dataset. Kim FT produced 1.6–5.6× less instrument bleed into the vocal stem. Ensembles and cascades were rejected — quality gains didn't justify latency cost. Locked recipe: Kim FT for vocals and instrumental, htdemucs_ft for drums, bass and other, htdemucs_6s for guitar, piano and synth. A one-line edit in recipe.py swaps any stem's model — synced via a tri-copy identity test in CI.

Billing & Quota Architecture

End-to-end Stripe: Payment Links → checkout.session.completed webhook → HMAC signature verification → tier flip in app_metadata via service role. Monthly quota persists as usage_month (UTC "YYYY-MM") and usage_minutes in app_metadata, surviving redeploys; a stale month auto-resets. The over-cap check fires before the ffmpeg duration probe — an unprobeable upload would otherwise bypass an exhausted balance. Verified with a live test-mode card checkout.

Safari AudioContext Unlock

The multitrack stem player played silently on Safari — scrubber advanced, currentTime moved, no audio. Classic Safari muted AudioContext until a user gesture. Fix: unlockAudio() on first pointer or keyboard event, priming the AudioContext with a 1-sample silent buffer. Browser tooling is Chromium-only, so verified via an injected-tone analyser measuring output RMS against a 440 Hz reference.

Dependency-Free ZIP Assembly

"Download all stems" required a single zip file. A zip library would break the dependency-free frontend constraint. Wrote ~40 lines of inline ZIP: STORE compression (audio barely compresses, so DEFLATE adds overhead without benefit), a CRC32 lookup table, and Blob-parts concatenation. Verified by capturing the Blob as base64 and running unzip -t — all CRC32 checksums passed, each stem held correct audio.
