Projects

Producer matching

In Development Studios

indevelopmentstudios.com ↗

A website where music producers upload a track and get matched with other producers based on how the music sounds, not on follower counts.

What I did

  • Built audio analysis that gives each track a fingerprint, tempo, key, and a genre prediction.
  • Built matching that returns 3 results from the same subgenre and 2 from other subgenres.
  • Built accounts, free and paid plans, and plan limits enforced in the database.
  • Found that a signed-in user could change their own plan from the browser. Moved plan data to a field only the server can write, then confirmed the fix against the live database.

Where it applies

  • Define the goal first. Matching on sound meant deciding what to measure before building. The same step applies to writing requirements for any project.
  • Check your own work for weak points. I tested whether users could get around the limits and found a gap. The same habit applies to reviewing a quote, a contract, or a forecast.
  • Balance precision and variety. The 2 outside-subgenre results keep matches from all looking alike. The same tradeoff shows up when prioritizing accounts or choosing between safe and new options.

Stem separation

ID.ai

idai.indevelopmentstudios.com ↗

A tool that splits a song into separate parts: vocals, drums, bass, guitar, piano, and more, up to 10 in total.

What I did

  • Tested several AI models on electronic tracks and picked the one with the least instrument sound leaking into the vocals (1.6 to 5.6 times less than the other model tested).
  • Connected Stripe payments to paid plans, with monthly usage limits set from compute cost.
  • Added automated tests and accessibility checks.
  • Fixed a bug where audio played silently in Safari.

Where it applies

  • Compare options with evidence. I tested the models instead of choosing by reputation. The same method applies when evaluating sales tools at work.
  • Set limits from cost. Usage caps were sized so each plan covers its compute cost. The same logic applies to pricing and discounting.
  • Test before release. Automated tests catch problems before customers do. This applies to any process that gets repeated.
